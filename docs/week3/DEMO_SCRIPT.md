# 球路參謀五分鐘 Demo 腳本

日期：2026-11-11（Asia/Taipei）。搭配九頁成果簡報 `deliverables/球路參謀_成果簡報_v5.pptx`。下列秒數是排練配置，總計 5:00；實際影片長度以錄製檔為準。

## 展示前準備

1. 開啟 [正式網站](https://happy123903.github.io/pitchadvisor-tw/)，確認模型 `week2-sequence-v1`、訓練截止 `2024-08-14`。等球員名單與推論完成再開始計時。
2. 同時開啟本機完整模式。於已安裝環境的專案根目錄執行：

   ```powershell
   rtk proxy powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\Start-Offline.ps1
   ```

   入口為 `http://127.0.0.1:8765/`。本機環境與前端必須事先備妥；臨場斷網後才安裝依賴並非本備案。啟動詳細要求以 [OFFLINE_GUIDE.md](OFFLINE_GUIDE.md) 為準。
3. 預先選擇鋼龍、陳傑憲，保持 0 壞 0 好、0 出局、壘上無人、無歷程。另開固定案例分頁，確認三組案例都能載入。
4. 將畫面放大到可閱讀，收起開發者工具。若沒有麥克風，錄製影片須明確標註為操作錄影，不能聲稱含口述音軌。

一次隔夜休眠後的真實喚醒觀測為 **51.514 秒**，首個請求先於 25.23 秒逾時，再以有限重試就緒。這不是等待時間保證，展示前仍需預熱。本機完整推論及固定案例是兩種不同備案。

## 固定案例對照

來源：[cases.json](../../web/public/demo/cases.json)。三組回應均由實際凍結模型預先產生，案例切換不會產生新的 API 推論。

| ID | 畫面名稱 | 投打與情境 | 可核對內容 |
|---|---|---|---|
| `count-only` | 一般情境：無已投球歷程 | 鋼龍對陳傑憲，0–0、0 出局、空壘 | 空歷程，直接對戰 65 球，情境 9,576 球。 |
| `history-two` | 完整歷程：兩球後的下一球 | 同組投打，SI 壞球、CU 看球好球，1–1 | 兩球、缺分區 1 球、缺球速 1 球，情境 3,959 球。 |
| `small-matchup` | 少量樣本：查看資料支持與集合 | 鋼龍對陳致嘉，1–2、1 出局、一壘有人 | 打者 6 球，直接對戰 0 球，情境 974 球。球種集合包含 CH、CU、SI、SL。 |

投手、打者、直接對戰及情境樣本的分母不同，不能加總成一個「可信度百分比」。分區集合可能很大，例如 `history-two` 涵蓋全部 13 區，不能只因名目 90% 就稱為精確定位。

## 可直接回答評審的問題

- **為何最後沒有用 GRU？** 相同驗證集下未明確勝過歷程 LightGBM，依事前選模規則採較簡單者，保留 GRU 與消融結果。
- **模型勝過基準嗎？** 2025 全部共同可用樣本的球種 log loss 較差 2.27%，線上名單內改善 3.56%。完整報告分別列出，沒有用較好的子集代表全部。
- **90% 是否代表這次推薦有九成成功？** 不是。它是集合的名目覆蓋目標，2025 球種全體實測 83.74%，而且覆蓋不等於推薦成功率。
- **是否證實可降低失分？** 尚未。推薦依歷史觀測條件結果及訓練期失分價值排序，選球偏差、人工座標和缺少瞄準意圖限制因果解讀。
- **斷網後是否還能改情境？** 本機完整模式可以重新推論。固定案例只能切換預存案例，介面會清楚標示唯讀。
