# 第二週執行與驗收設定

設定日期：2026-11-10。依 v3 第 8–14 天交付範圍執行；本文件在比較第二週模型結果前固定驗收規則。

## 目標與已知現況

第一週的頻率基準已能在線上推論，但尚無序列、打者條件、校準或預測集合。第二週需交付真實的序列摘要 LightGBM、GRU 多任務比較、條件結果／候選推薦、校準／conformal、小樣本與消融，以及可編輯歷程的前端。會員系統與研究選配 TabPFN／Transformer 不在本週必要範圍。

## 資料與公平比較

- 訓練截止 2024-08-14；驗證自 2024-08-16 至 2024-09-12 前；校準自 2024-09-12 起。沿用逐場切分，不變更既有邊界。
- 2025 最終測試集不訓練、不選模、不校準、不計算模型指標。
- 所有球員索引、樣本統計、速度正規化、座標抖動尺度與 ΔRE 價值僅由訓練期建立。
- 模型在同一批驗證樣本／目標遮罩上比較。分區缺標籤只遮罩該任務；特殊結果明列排除量，不塞入不符的五類。
- 序列僅含當前打席、待預測球之前的事件。結果模型可使用候選球種與分區，球種／分區目標不得看到當球真值。

## 比較與決策規則

- 比較聯盟球數、投手頻率、情境 LightGBM、序列摘要 LightGBM、GRU。
- 驗證球種 log loss 為主，另報 top-1／top-2、13 區及結果 log loss、ECE、小樣本分組、缺值與樣本數。
- 主要指標差距在 0.005 nats 內時，偏好較簡單、較易部署的模型。GRU 必須具備不劣的整體證據與服務資源結果才採用，不因主打名稱直接上線。
- 免費服務驗收預留資源：服務記憶體低於 400 MiB，暖機端點 p95 低於 500ms；超出者先優化／退回通過的較簡單模型，無自動付費升級。
- 消融：序列有無、embedding 收縮有無、座標抖動有無、單任務／多任務；報實際結果與固定運算條件，不宣稱一次小型試驗能代表所有配置。

## 校準與不確定性

- 獨立校準期再依完整日期，約以 40%／30%／30% 分成溫度擬合、conformal 分位數、覆蓋率 audit；實際日期與筆數記入產物。
- 初始名目覆蓋率為 90%，使用有限樣本分位數；實測覆蓋率與集合大小由未參與擬合及分位數計算的 audit 子集評估。
- 時間序列存在分布變化，不宣稱 exchangeability 保證；顯示分布外／稀疏與觀察資料偏差警語。
- 預測集合不等同推薦成功率。推薦依條件結果機率乘以訓練期 ΔRE 價值排序，保留候選樣本支持與因果限制。

## 系統交付

- 共用序列 schema：球種、分區或未知、球速或未知、結果；同打席從 0–0 還原，最多 16 球，終結打席或與目前球數不符時明確報錯。
- 訓練可用 CPU PyTorch；線上只載 LightGBM／NumPy 權重及固定校準器，不把整個 PyTorch runtime 放入 Render。
- 版本化單一 JSON 模型包，UTF-8 LF 位元組寫入與 SHA-256 校驗；保留第一週模型，提供可回復的固定版本。
- 本機測試、正式建置、模型一致性與資源驗證通過後，再更新 Supabase 模型、Render 與 Pages，實查線上新功能。
