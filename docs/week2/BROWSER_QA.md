# 第二週前端瀏覽器驗證紀錄

驗證日期：2026-11-10（Asia/Taipei）。本紀錄描述實際完成的本機瀏覽器操作，不代表正式網站部署驗收。

## 環境與方法

- 前端：專案 Vite 開發伺服器，`http://127.0.0.1:5173/`。
- 後端：專案 FastAPI，`http://127.0.0.1:8000/`；前端透過既有 `/api` 代理呼叫。
- 瀏覽器：Playwright CLI 啟動的 **Chrome 有視窗模式**（`--browser chrome --headed`），不是 headless，也沒有使用使用者登入中的瀏覽器。
- 畫面尺寸：桌面 1440 × 1000、手機寬度 390 × 844 CSS pixels。手機檢查採調整 viewport，沒有宣稱完成實體手機或 iOS 裝置測試。
- 使用實際按鈕、下拉選單與輸入框操作；較長的 16 球邊界檢查以 CLI `run-code` 重複正常 Playwright 點選與填寫。沒有注入 React state，也沒有 mock 推論回應。
- DOM 讀取與 `page.evaluate` 僅用於確認顯示文字、控制項停用狀態及頁面寬度。
- 截圖以 CSS pixels 儲存，已逐張開啟檢視；主要區塊另擷取元素截圖，保留內容細節。

先載入第一週基準模型，確認能力尚未啟用時的降級行為。第二週模型完成後，重新啟動本次擁有的 API，使用 `artifacts/week2`、`MODEL_VERSION=week2-sequence-v1`，再執行完整互動檢查。實際畫面採用 `lightgbm_history`，不是用前端預填數字模擬成果。

## 模型與可信度畫面核對

模型比較表讀取 API 的驗證資料，並標示目前採用 `lightgbm_history`。畫面能切換三項任務，對照聯盟頻率、投手收縮頻率、情境 LightGBM、歷程 LightGBM 與 GRU。選擇理由及規則直接來自模型摘要。

保留校準稽核畫面讀到的實測值如下，沒有改成名目目標值：

| 任務 | 稽核樣本 | 實測覆蓋率 | 平均集合大小 |
|---|---:|---:|---:|
| 球種 | 3,196 | 89.8% | 2.52 |
| 落點 | 3,193 | 90.3% | 10.27 |
| 投球結果 | 3,196 | 89.5% | 3.58 |

畫面同時呈現校準前後 ECE、溫度校準／集合門檻／保留稽核日期與筆數，以及時間分布改變可能影響覆蓋率的限制。2025 最終測試尚未評分的狀態由模型摘要如實呈現。
